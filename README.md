# オリキャラメーカー (Original Character Variation Maker with Gemini AI)

名古屋芸術大学 オープンキャンパス 2026.7.24 ワークショップ用Webアプリケーション  
手描きのイラストや線画をもとに、Google Gemini API を活用して、ゲームや Web アプリで使うキャラクターの向き・ポーズ・表情のバリエーションを生成します。

---

## 動作モード

本アプリは **アクセス元のホスト名** によって自動的に動作モードが切り替わります。

| | オンライン版 (本番デプロイ) | ローカル版 (開発用) |
|---|---|---|
| **判定条件** | 本番ビルドを `localhost` 以外で公開 | 開発サーバーでの起動（どのURLでも）、または `localhost` / `127.0.0.1` / `0.0.0.0` |
| **ログイン** | Google OAuth (nua.ac.jp ドメイン限定) | 不要 — ログイン画面と説明ページをスキップし、線画作成から開始 |
| **スタミナ制限** | あり (1時間1回復・最大50) | なし — 無制限 |
| **プロジェクト保存** | Supabase DB に自動保存 | なし — ブラウザのメモリ上のみ (リロードで消失) |
| **画像生成 (Gemini API)** | Edge Function 経由 (APIキーはサーバー側で管理) | `.env` に記述した APIキーでブラウザから直接呼び出し |
| **管理者判定** | `d-mukai@nua.ac.jp` のみ | 常に管理者扱い |
| **ログアウトボタン** | 表示 | 非表示 |

## 主な機能とワークフロー

### Step 1: 線画を描く
- **全画面キャンバス**: ペン / 消しゴム、線の太さ調整、Undo、一括クリア、位置移動。タッチ操作対応。
- **カメラ撮影 & 画像アップロード**: 手描きの紙をカメラで撮影、またはローカル画像をアップロード。
- **クロマキー透過処理**: 生成画像の背景色 (#FF00FF) を自動検出しアルファ透過。キャラクター内部の色は保護。

### Step 2: 画風とキャラクター設定
- **8種類のプリセット画風 + オリジナル**: コピック風、アニメセル画風、水彩画風、クレイ風、レトロポップ風、色鉛筆風、3Dフィギュア風、ピカソ風。
- **線画維持率スライダー**: 手描き線の特徴を残す割合を 20%〜100% で調整。
- **キャラクター詳細設定**: 自由記述でキャラクターの特徴を指定。
- **操作モード**: やさしいモード (ひらがな表記) / 通常モード / エキスパートモード (全文プロンプト自由記述)。

### Step 3: アセット一括生成（Lite モデル）
基本イラストを見本に、選んだアセットをまとめて生成します。一括生成は常に `gemini-3.1-flash-lite-image` を使用します。
- **2D RPG** (16枚): 目線の高さから見た 8方向 × 立ち・歩き
- **2D SLG** (16枚): 俯瞰45°から見た 8方向 × 立ち・歩き
- **2D ACT** (15枚): やや右向き。立ち・歩き1〜3・走り1〜3・構え・パンチ・キック・ジャンプ・しゃがみ・ダメージ・ダウン・勝利
- **2D ノベル** (11枚): 上半身の表情10種（平常・笑み・爆笑・幸せ・怒り・不安・恐怖・驚き・泣き・悲壮）＋全身画
- 歩き・走りなどの連続コマは、直前のコマも参照して生成し、アニメーションとして繋がるようにします。

### Step 4: 微調整・バリエーション追加
- **個別修正**: 指示文で1枚ずつ修正（高品質 / Lite を選択可）。直近3版まで「1つ前に戻す」が可能。
- **作り直し・名前変更・削除・PNG個別保存**。
- **新しいバリエーション**: 基本イラスト＋生成済み画像・アップロード画像・手描きラフ（最大3枚）を参照して新規作成。
- **アニメーション確認**: 方向ごとの立ち/歩き、ACT の歩き・走りをループ再生。背景（透過/白/黒/フィールド）切替。

### Step 5: 保存・ダウンロード
- オンライン版ではすべての画像がアカウントに自動保存されます。
- 透過PNGをアセットごとのフォルダに分けて ZIP でダウンロード（全体 / アセット単位）。

## ローカル開発環境のセットアップ

### 1. 依存パッケージのインストール

```bash
npm install
```

### 2. 環境変数の設定

プロジェクトルートの `.env` ファイルに Gemini API キーを記入します。

```env
VITE_GEMINI_API_KEY=your_gemini_api_key_here
```

> `VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY` はアプリ起動時に読み込まれるため、ローカル版でも削除しないでください（ローカル版では実際の DB・認証への通信は行いません）。

### 3. 開発サーバーの起動

```bash
npm run dev
```

ブラウザで `http://localhost:5173` にアクセスします。  
ログインなし・スタミナなし・DB保存なしで、すぐにアプリを操作できます。  
APIキーが設定されていれば画像生成もそのまま動作します。

### 4. ビルド

```bash
npm run build
```

`dist/` フォルダに本番用ファイルが出力されます。

## オンライン版 (本番デプロイ) について

本番環境では以下が有効になります。

- **Google OAuth 認証**: `nua.ac.jp` ドメインのアカウントのみアクセス可能。
- **Supabase DB**: プロジェクト設定は DB、バリエーション画像は非公開 Storage（`character-images`）に自動保存されます。
- **スタミナ制限**: ユーザーごとに最大50、1時間に1回復。管理者 (`d-mukai@nua.ac.jp`) は無制限。
- **Edge Function 経由の画像生成**: Gemini API キーはサーバー側シークレットとして管理。クライアントには露出しません。

デプロイ先の Supabase プロジェクトに以下のシークレットが必要です。
- `GEMINI_API_KEY`: Gemini API キー (Edge Function 用)
